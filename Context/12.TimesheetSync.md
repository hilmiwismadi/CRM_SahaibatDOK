# 12. Timesheet mingguan (`/sync/timesheet`)

Dibuat 2026-10-11. Dokumen pendamping: [[9.DailySyncInput]] (pola script console yang sama), [[10.VpsAccessAndDeploy]] (deploy).

## Tujuan
Menyiapkan **draft timesheet mingguan** untuk `https://sales.sahaibat.com/timesheet` dari riwayat chat WA, diperbarui per minggu (akhir minggu). Output halaman = **script console** yang tinggal di-paste; tabel draft boleh diedit dulu dan script mengikuti isi tabel. Halaman dan API hanya membaca; tidak menulis ke DB VPS maupun ke sales.sahaibat.com.

## Struktur sales.sahaibat.com/timesheet (dibaca 2026-10-11)
- Navigasi minggu ‹ › (Senin–Minggu), status minggu **Draft** atau **Submitted** (terkunci, menunggu persetujuan manajer), kartu Total logged / Entries / Weekly target (40h).
- Form **Add an entry**: Day (dropdown, value `YYYY-MM-DD`), Hours (number, mis. `1.5`), Category (`prospecting`, `demo`, `follow_up`, `admin`, `travel`, `training`), Account (dropdown: "— none —", "Prospecting (general)", dan 17 klinik/praktik dari CRM tim; value berupa UUID lead), Notes (teks bebas).
- Tiap entri punya ikon 🗑; setelah ada entri muncul tombol **Submit for approval** (hanya dikliking oleh user; setelah submit tidak bisa diedit).
- Contoh minggu 21–27 Sep (22.8 jam, 5 entri): satu entri per hari + kategori; Notes berisi daftar kegiatan dengan jam, mis. `Gmeet (8.30-9.30), Email n FU (9.30-10.00), Cold Chat (10.15-11.30)`. Hari Senin 21 tidak bisa diinput (dicatat ke Selasa dengan catatan).
- API (terlihat dari network tab): `GET /api/timesheets?week=<Senin>` → `{timesheet:{id,periodStart,periodEnd,status,totalHours}}`; `GET /api/time-entries?week=<Senin>` → `{entries:[{id,timesheetId,entryDate,hours,category,notes,leadId,taskId,...}]}`; tombol Add memanggil `POST /api/timesheets` (membuat header minggu) lalu `POST /api/time-entries`. **Body POST belum dicatat** (sengaja tidak dites tulis).
- Uji 2026-10-11: satu entri dummy (Senin 5 Okt, 1.5 jam, Prospecting, "[UJI COBA] entri dummy, abaikan") ditambahkan lewat form ke draft 5–11 Okt. **Hapus manual (🗑) sebelum submit minggu itu.**

## Keputusan (user, 2026-10-11)
- Isi dari riwayat chat saja; tidak perlu akurat, cukup ada rekap jumlah: lead dichat/dikontak, lead baru, konfirmasi nomor, pitch, membalas, follow-up, usulan jadwal/Gmeet.
- Notes **full bahasa Indonesia**.
- Target ±40 jam/minggu, wajar **38.5–44 jam**, jangan terlalu absolut. Sabtu/Minggu boleh diisi tapi minim (1–2.5 jam, hanya bila ada chat).
- Kategori: hari cold chat = Prospecting, balasan/follow-up = Follow-up, demo/pertemuan = Demo, CRM/daily log/timesheet = Admin.
- **Manager membaca dua angka: berapa client yang dichat minggu itu dan berapa demo.** Karena itu semua angka di Notes harus sinkron dengan rincian di halaman (bisa ditelusuri per lead), dan Demo hanya dari data resmi, bukan tebakan kata kunci (keputusan 2026-10-11).
- **Jam per hari (2026-10-12):** hari kerja sebelum 1 Okt = 3–5 jam; mulai 1 Okt rata-rata 8 jam (minggu penuh 38.5–44). Minggu 28 Sep–4 Okt dan 5–11 Okt sama-sama bisa diisi walau sudah lewat.
- **Notes menyebut nama lead** ("Follow-up 12 lead: A, B, … 6 lead membalas: A (ringkasan); …"). Ringkasan = "Ringkasan Claude" per lead per hari (`sync_daily_summaries`, ditulis sesi Claude Code seperti di dailylog); bila belum ada, memakai kutipan singkat balasan.
- Isi akhir minggu. Minggu 5–11 Okt: ditambah pekerjaan "pengembangan dan update tools CRM pribadi" (masuk Admin, +1.5 jam per hari kerja). **Minggu 11 Okt awalnya dikosongkan, lalu (2026-10-12) diisi sebagai hari Admin saja (2 jam): "Kegiatan administratif (rekap data, daily log, timesheet); pengembangan dan update tools CRM pribadi…"**. Aturan umum: hari Sabtu/Minggu tanpa chat keluar, saat ada pekerjaan tambahan, otomatis jadi satu baris Admin 2 jam.
- Senin yang tidak bisa diinput: dilewati.
- **Submit mingguan selalu oleh user.** Perubahan ke CRM (menjalankan script) ditunda sampai user minta.

## Cara kerja
- `GET /api/sync/timesheet?week=<tanggal mana pun>&skip=<tgl,tgl>&extra=<teks>&target=<jam>` (`apps/web/src/app/api/sync/timesheet/route.ts`): agregasi `wa_messages` per hari WIB → `days[]` (statistik) + `rows[]` (draft). Hari setelah hari ini tidak pernah diisi; Sabtu/Minggu hanya bila ada chat.
  - *Lead baru* = pesan pertama kontak itu terjadi hari tsb (cold chat); selain itu = follow-up.
  - *Konfirmasi* = pesan "apakah benar ini kontak …"; *Pitch* = pesan "Perkenalkan saya …"; *Bahas jadwal* = lead yang percakapannya (non-pitch; balasan lead > 200 karakter diabaikan karena biasanya bot) menyebut gmeet/zoom/wawancara/jadwal/hari/pukul — hanya **petunjuk** dengan kutipan pesan, **bukan** jumlah demo.
  - **Demo = tabel `lead_appointments`** (menu Jadwal; jenis `demo_gmeet`/`visit`/`other`) dengan `startsAt` di minggu itu, status bukan `cancelled`, dan dihitung bila `done` atau `scheduled` yang sudah lewat. Tiap demo jadi satu baris Demo (jam = durasi, Account = nama lead). Bila hasilnya salah, perbaiki status di menu Jadwal.
  - Ringkasan mingguan (`summary`): client unik dichat, lead baru, client membalas, demo. Kalimat "Rekap minggu ini: … client dichat …, … demo/pertemuan" ditempel ke Notes baris Admin hari terakhir yang terisi.
  - Rincian per lead per hari (`days[].leads`): nama, lead baru/follow-up, jenis pesan yang kami kirim, membalas atau belum (kutipan balasan), dan kutipan pembahasan jadwal.
- `apps/web/src/lib/timesheetPlan.ts` (`planWeek`): target mingguan deterministik per minggu (38.5–44, sekitar 40), jam per hari sedikit mengikuti jumlah chat, dibagi ke kategori, dibulatkan 0.25 jam, lalu minggu penuh dikunci ke 38.5–44.
- Halaman `/sync/timesheet` (`apps/web/src/app/sync/timesheet/page.tsx`, tab "Timesheet" di `SyncTabs`): pilih minggu, kartu ringkasan mingguan (client dichat, lead baru, membalas, demo), daftar demo dari Jadwal, rekap chat per hari (klik baris → rincian lead + kutipan balasan + kutipan jadwal) dengan centang hari yang diisi, kolom pekerjaan tambahan, tabel entri yang bisa diedit (hari, kategori, akun, jam, catatan, hapus/tambah baris), total jam vs rentang wajar, dan script yang selalu mengikuti tabel. Editan tersimpan di `localStorage` per minggu; tombol "Hitung ulang draft" membuang editan. Default minggu 5–11 Okt: Minggu 11 dikosongkan + pekerjaan tambahan CRM.
- **Script** (`APPLY = false` = dry run): mengisi **form "Add an entry" halaman itu sendiri** (set Day/Category/Account/Hours/Notes lalu klik Add), jadi memakai request yang sama persis dengan halaman, tanpa menebak body API tulis. Hanya membaca `GET /api/timesheets` (minggu harus `draft`) dan `GET /api/time-entries` (lewati entri yang sama: tanggal + kategori + catatan). Akun dicocokkan dari teks dropdown; bila tidak ada dikosongkan dengan peringatan. Setelah tiap Add, memverifikasi lewat GET. Selector form dan GET sudah dites (dry run) di halaman asli 2026-10-11.

## Alur mingguan: Claude membaca DB, menulis ringkasan, lalu /sync/timesheet memakainya
Ringkasan per lead per hari ("Ringkasan Claude") **ditulis oleh sesi Claude Code**, bukan aplikasi (tidak ada API Claude di app; keputusan 2026-10-01). Halaman `/sync/timesheet` hanya **membaca** ringkasan itu dari tabel `sync_daily_summaries` dan menaruhnya di Notes. Urutan tiap minggu:

1. **Fetch data chat (Claude yang baca, user yang menjalankan SSH).** Claude tidak boleh SSH ke produksi sendiri (diblok pengaman); user menjalankan dengan `!`. Sumbernya satu query: `scripts/crm-sync/timesheet-chats.sql` — tabel `wa_messages` + `wa_contacts` + `leads`, hanya lead yang **membalas** (inbound tidak kosong) pada hari itu dan **belum punya** ringkasan di `sync_daily_summaries`. Ganti rentang tanggal di baris `between ... and ...` (Senin–Minggu minggu itu), lalu:
   ```
   ! ssh -i /d/Hilmi/Coding/Sahaibat/VPS_DW/DWSSH.pem DzakiWismadi@103.93.162.31 "docker exec -i mapping-db-1 sh -c 'psql -U \$POSTGRES_USER -d \$POSTGRES_DB -A -F \"|\" -t'" < /d/Hilmi/Coding/Sahaibat/Mapping/scripts/crm-sync/timesheet-chats.sql > /d/Hilmi/Coding/Sahaibat/Mapping/scripts/crm-sync/timesheet-chats.txt
   ```
   Hasil: `timesheet-chats.txt`, baris `tanggal|lead_id|nama|jam WIB|arah|isi`. Perhatian: `sent_at` bertipe timestamp tanpa zona berisi UTC, jadi query memakai dobel `AT TIME ZONE` (UTC lalu Asia/Jakarta); satu kali ini pernah salah dan chat tercampur antar hari.
2. **Claude menulis ringkasan** untuk setiap lead-hari di file itu (1–3 kalimat, bahasa Indonesia, apa yang dibalas lead dan hasilnya: setuju/menolak/minta surat/jadwal wawancara-Gmeet; bukan salinan chat). Dibuat lewat skrip kecil yang menghasilkan `scripts/crm-sync/summaries/<tanggal>.json` dan `.sql` (format sama dengan 2026-10-07/09: `INSERT INTO sync_daily_summaries (lead_id, date, summary) ... ON CONFLICT (lead_id, date) DO NOTHING`, dollar-quote `$q$`).
3. **User menerapkan SQL ke DB VPS** (satu perintah `!`, input dari file `.sql` lewat `docker exec -i mapping-db-1 ... psql`). Tanpa langkah ini ringkasan tidak muncul di halaman.
4. **Buka `/sync/timesheet`**, pilih minggu. API `/api/sync/timesheet` membaca: `wa_messages` (hitungan + siapa saja), `lead_appointments` (demo), dan `sync_daily_summaries` (ringkasan per lead per hari, kunci `date|leadId`). Notes tiap baris Prospecting/Follow-up berformat: "Cold chat ke N lead baru: A, B, … ; konfirmasi nomor X, pitch Y. M lead baru membalas: A (ringkasan); …" dan "Follow-up N lead: …. M lead membalas: A (ringkasan); …. Membahas jadwal … dengan K lead: …". Ringkasan dipotong ±150 karakter di batas kata. Lead membalas yang belum ada ringkasannya memakai kutipan balasan (tanda hari itu belum diringkas; di rincian per lead tampil peringatan kuning).
5. Cek tabel, edit bila perlu, lalu **Copy script** (default `APPLY = true`; kotak centang bisa diubah ke dry run) dan jalankan di sales.sahaibat.com. Submit tetap dilakukan user.

**Hubungan dengan `/sync/dailylog`:** kolom "Ringkasan Claude" di sana memakai tabel `sync_daily_summaries` yang sama (input harian: `9.DailySyncInput.md`). Ringkasan yang diisi untuk salah satu halaman otomatis muncul di halaman lainnya, dan query `timesheet-chats.sql` otomatis melewati lead-hari yang sudah punya ringkasan. Beda query: `timesheet-chats.sql` = rentang minggu, hanya lead yang membalas; `dailylog-chats.sql` = satu hari, semua lead termasuk yang belum membalas (untuk dailylog).

Aturan jam: hari kerja sebelum 2026-10-01 3–5 jam; mulai 1 Okt rata-rata 8 jam (minggu penuh 38.5–44 jam); akhir pekan minimal.

## Kendala yang sudah terjadi (hindari lagi)
1. **Huruf "s" hilang di Notes** (2026-10-12): regex di `gist()` (`timesheetPlan.ts`) kehilangan backslash saat dipatch (`/\s+/g` → `/s+/g` mengganti setiap "s" dengan spasi; `/\.$/` → `/.$/` membuang karakter terakhir). **Tool Bash/heredoc/`node -e` memakan backslash** — tulis regex dan perintah yang berisi `\` dengan Edit/Write, lalu cek hasil akhirnya di file (mis. `Grep` untuk `\s`).
2. **Draf lama di browser menimpa hasil baru.** Editan tabel disimpan di `localStorage` (`sync-timesheet-v2-<minggu>`) dan menang atas hasil hitung ulang, jadi setelah logika berubah halaman masih menampilkan format lama ("Follow-up 12 lead, 6 lead membalas", baris Demo "Koordinasi jadwal…"). Perbaikan: klik **Hitung ulang draft**; dan **naikkan nomor versi kunci** (`storageKey` di `page.tsx`) setiap kali format output `planWeek()` berubah.
3. **Query chat salah zona waktu.** `wa_messages.sent_at` = timestamp tanpa zona berisi UTC; `x AT TIME ZONE 'Asia/Jakarta'` langsung menggeser jam ke arah yang salah (jam mundur 14 jam, chat antar hari tercampur). Gunakan dobel: `(sent_at AT TIME ZONE 'UTC') AT TIME ZONE 'Asia/Jakarta'` (sudah di `timesheet-chats.sql`).
4. **Deploy gagal karena file tidak lengkap.** Jika `route.ts`/`page.tsx` naik tapi `timesheetPlan.ts` tidak, build gagal dengan error tipe (`DayDemo` tidak diekspor dll.) dan ikut menggagalkan build fitur lain di repo yang sama (`/demoemr`). Selalu scp **ketiga file** (`lib/timesheetPlan.ts`, `app/api/sync/timesheet/route.ts`, `app/sync/timesheet/page.tsx`) lalu build. Satu perintah per `!`; baris `! ...` yang ikut tertempel di dalam satu blok bash membuat exit code 1 meski build sukses — baca log, bukan exit code. Cegah dua build bersamaan (sesi Claude lain bisa sedang deploy).
5. **SSH terputus di tengah build** ("Connection reset by peer"): build di server bisa tetap selesai sendiri. Jalankan build di latar belakang server: `ssh ... "cd ~/Mapping && nohup sh -c 'docker compose build web && docker compose up -d --no-deps web' > /tmp/web-build.log 2>&1 &"`, pantau dengan `ssh ... "tail -n 6 /tmp/web-build.log"` sampai muncul `Container mapping-web-1 Started`. Pesan `mapping-web-1 Running` tanpa `Recreate` = image sama dengan yang sudah berjalan (build sebelumnya sudah menggantinya); cek `docker ps` (`Up N minutes`).
6. **Demo = 0 di kartu** bila Gmeet belum dicatat di menu Jadwal (`lead_appointments`). Demo tidak pernah dihitung dari tebakan chat. Catat dulu di Jadwal, lalu Hitung ulang draft.
7. "Membalas" mencakup balasan otomatis (bot auto-reply jam praktik), jadi angkanya bisa lebih besar dari lead yang benar-benar menanggapi; ringkasan Claude di Notes menandai "hanya balasan otomatis".
8. Claude tidak bisa SSH ke produksi sendiri (pengaman otomatis menolak) dan ekstensi Chrome tidak selalu terhubung; ambil data DB lewat perintah `!` yang dijalankan user dengan keluaran ke file (`> timesheet-chats.txt`), lalu Claude membaca file itu.
