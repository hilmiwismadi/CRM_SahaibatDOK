### 2.2 Prinsip

1. **Note = indeks, bukan salinan.** Note brain merangkum 5–15 baris, lalu menunjuk file kode / doc lama. Detail tetap di doc asli atau di kode.
2. **Satu konsep, satu note kanonik.** Kalau suatu definisi (brown pin, deploy, sent_at) muncul di banyak doc, buat 1 note kanonik. Doc lama cukup diberi baris `> Kanonik: [[...]]`.
3. **Setiap note fitur wajib punya "Change Impact".** Ini nilai utamanya: daftar file yang harus ikut diubah.
4. **Status eksplisit** di frontmatter: `aktif | snapshot | arsip | usang`.
5. **Ramah Claude.** Path ditulis lengkap relatif dari `Mapping/`, tanpa rahasia, dan ringkas, karena note ini akan dibaca AI juga.
