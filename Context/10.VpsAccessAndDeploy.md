## 2. Model izin: apa yang otomatis, apa yang tidak

Claude Code punya dua lapis yang berbeda — jangan tertukar:

1. **Permission rule** (`.claude/settings.local.json`). Sudah ada di `D:\Hilmi\Coding\Sahaibat\.claude\settings.local.json`:
   ```json
   { "permissions": { "allow": [
       "Bash(ssh -i VPS_DW/DWSSH.pem:*)",
       "Bash(scp -i VPS_DW/DWSSH.pem:*)" ] } }
   ```
   Rule ini mencocokkan **teks perintah persis dari awal**. Jadi hanya cocok kalau perintah ditulis `ssh -i VPS_DW/DWSSH.pem ...` dari folder `Sahaibat`. Perintah dengan `../VPS_DW/...` atau `/tmp/dw.pem` tidak cocok dan akan minta konfirmasi.
2. **Pemeriksa mode otomatis** (auto mode classifier). Ini menilai *dampak* aksi, bukan teks perintah. Aksi bertipe **"Production Deploy"** (scp kode ke server produksi + `docker compose build/up`) **ditolak** walau rule SSH ada.

Hasil di sesi ini:

| Aksi | Hasil |
|---|---|
| ssh read-only (`docker ps`, `md5sum`, `psql select`, `scp` dari VPS ke lokal) | Jalan |
| ssh: backup `pg_dump` + `scp` kode ke VPS + `docker compose build web` + `up -d` | **Ditolak** (Production Deploy) |
| Deploy yang sama, **dijalankan user sendiri** dengan awalan `!` di terminal Claude | Jalan |
| `scp` file `.json` data ke `scrape-output/` VPS + `curl` ke `/api/admin/import-staging` dari dalam VPS | Jalan (setelah deploy) |

Aturan praktisnya:

- Menambah allow rule SSH **tidak** membuka blokir "Production Deploy". Jangan habiskan waktu mencari rule yang "pas", dan jangan memecah perintah ditolak menjadi potongan kecil untuk memutar blokir.
- Alurnya: Claude memeriksa dan menyiapkan perintah → **user yang menjalankan deploy kode** dengan `! <perintah>` → Claude melanjutkan verifikasi, upload data, dan impor.
- Satu perintah per `!`. Kalau beberapa baris `!` ditempel sekaligus ke satu input, Bash menganggapnya satu skrip dan hasilnya sulit dibaca (kebetulan di sesi ini tetap sukses, exit code 1 hanya dari baris `!` nyasar). Perintah yang lebih dari 2 menit (build Docker) pindah ke background otomatis dan hasilnya ada di file output yang ditunjuk notifikasi.
- Di terminal Claude, `!` menjalankan **Bash**, bukan cmd/PowerShell. `type`, `mkdir 2>nul`, dan `echo {json} > file` ala cmd tidak jalan. Untuk menulis rule, lebih aman lewat `/permissions` atau minta Claude yang mengedit `settings.local.json`.

## 3. Urutan deploy kode yang sudah terbukti

Selalu **periksa dulu** sebelum menimpa; VPS bisa lebih baru dari catatan lama (catatan progress 2026-10-07 menyebut "kode belum di-deploy", padahal sebagian sudah).

1. Bandingkan file dengan checksum, abaikan CRLF/LF (Windows vs Linux membuat `diff` biasa menampilkan seluruh file berbeda):
   ```bash
   # di VPS
   md5sum apps/web/src/lib/leadAutoLabel.ts apps/web/src/lib/upsertLeadsFromStaging.ts apps/web/src/app/map/MapView.tsx apps/web/src/app/admin/scrapes/page.tsx docker-compose.yml
   # lokal: scp file VPS ke /tmp lalu  diff --strip-trailing-cr
   ```
   Waktu build kontainer (`docker inspect mapping-web-1 --format '{{.Created}}'`) juga menunjukkan versi apa yang aktif. Jangan timpa `docker-compose.yml` mentah dan **jangan `docker compose down -v`** (menghapus volume DB).
2. Backup database dulu:
   ```bash
   ssh -i ../VPS_DW/DWSSH.pem DzakiWismadi@103.93.162.31 'cd ~/Mapping && mkdir -p backups/pre-import-YYYYMMDD && docker exec mapping-db-1 pg_dump -U sahaibat sahaibat_mapping | gzip > backups/pre-import-YYYYMMDD/db.sql.gz'
   ```
   Backup sesi ini: `~/Mapping/backups/pre-import-20261007/db.sql.gz` (±9,7 MB, 1.545 leads).
3. Upload hanya file yang berbeda:
   ```bash
   for f in <file1> <file2>; do scp -i ../VPS_DW/DWSSH.pem $f DzakiWismadi@103.93.162.31:Mapping/$f; done
   ```
4. Rebuild hanya `web`, tanpa menyentuh `db`/`wa-bridge`:
   ```bash
   ssh -i ../VPS_DW/DWSSH.pem DzakiWismadi@103.93.162.31 'cd ~/Mapping && docker compose build web && docker compose up -d --no-deps web'
   ```
   CRM mati beberapa menit selama recreate. Verifikasi: `md5sum` VPS = lokal, dan `mapping-web-1` status `Up`.

## 4. Urutan impor data

Endpoint `POST /api/admin/import-staging` **tanpa autentikasi** dan hanya membaca nama file dari `scrape-output/` (di kontainer: `/app/scrape-output`, bind mount dari `~/Mapping/scrape-output`; nama dengan `/` ditolak).

1. Salin hanya file `<daerah>-dokter-klinik.json` (bukan `.raw.json`, bukan `.old-*`):
   ```bash
   cd Mapping/scrape-output
   scp -q -i ../../VPS_DW/DWSSH.pem a.json b.json DzakiWismadi@103.93.162.31:Mapping/scrape-output/
   ```
   Cek terlihat di kontainer: `docker exec mapping-web-1 ls /app/scrape-output`.
2. **Uji satu daerah dulu**, bandingkan `count(*) from leads` sebelum/sesudah dengan `newCount`:
   ```bash
   ssh ... 'curl -s -m 300 -X POST localhost:3000/api/admin/import-staging -H "Content-Type: application/json" -d "{\"fileName\":\"jember-dokter-klinik.json\",\"queryText\":\"jember-dokter-klinik (40 baris dokter praktik mandiri + klinik, 20 titik)\"}"'
   ```
   Respons berisi `mergeSummary`: `scannedCount`, `newCount`, `updatedCount`, `skippedCount`, `excludedCount`. Ini juga membuat satu baris `scrape_jobs` (muncul di `/admin/scrapes`), jadi `queryText` sebaiknya deskriptif.
3. Baru loop sisanya dalam satu ssh, lalu cek total dan distribusi label:
   ```sql
   select label,count(*) from leads group by 1 order by 2 desc;
   ```
   Query lewat `docker exec mapping-db-1 psql -U sahaibat -d sahaibat_mapping -tc "..."`.

Impor aman diulang: upsert berbasis `google_place_id` (lihat [[3.ScrapingQueryPatterns]]), jadi file yang sama tidak menggandakan lead. Meski begitu, tiap impor membuat `scrape_jobs` baru, jadi jangan diulang tanpa alasan.

## 6. Gotcha scrape lokal yang ikut terpakai sesi ini

- Kontainer gosom kadang **tidak keluar sendiri** setelah log `scrapemate exited` (hasil sudah tertulis penuh). Skrip berantai (`run-scrape.ps1` lalu `clean-scrape-region.mjs`) jadi tertahan. Solusi: pengawas yang `docker kill` kontainer begitu log berisi `scrapemate exited`. Kontainer yang keluar sendiri (mis. sragen) tetap normal.
- Docker Desktop harus menyala; saat memori bebas ±2 GB runner sebelumnya pernah dihentikan otomatis. Jalankan daerah berurutan, bukan paralel.
- Error `ERR_CONNECTION_REFUSED` sesaat di log tidak membatalkan run, tapi sebagian listing bisa terlewat; cek jumlah `place_id` per daerah (anggapan wajar ±200–260 untuk kabupaten, ±400 untuk malang/semarang/jember).
- Hapus `.json`/`.raw.json` parsial atau 1-byte sebelum scrape ulang; cadangkan dulu kalau mau membandingkan (`jember-dokter-klinik.old-91.json`).
- Hitung listing bersih dengan menghitung `"place_id"` di file `.json` setelah `clean-scrape-region.mjs`.

## 7. Filter daerah di `/map` (deploy 2026-10-07, sore)

**Masalah:** `/map` dulu memanggil `/api/leads` tanpa filter, jadi setelah impor (4.705 lead, tiap lead ikut kontak WA + pesan terakhir) halaman memuat ±7 MB / 6 detik sebelum ada titik yang tampil.

**Solusi:** pilih daerah dulu, hanya lead daerah itu yang dimuat.

| File | Peran |
|---|---|
| `apps/web/src/lib/mapRegions.ts` | Daftar 28 daerah: `key`, `label`, `terms` (substring alamat). **Tambah satu baris di sini untuk daerah scrape baru**; muncul di picker otomatis begitu ada ≥1 lead yang cocok. |
| `apps/web/src/app/api/leads/region-counts/route.ts` | `GET` → `{ total, regions: [{key,label,count}] }` (hanya daerah dengan count > 0). Ringan, dipanggil saat `/map` dibuka. |
| `apps/web/src/app/api/leads/route.ts` | Parameter baru `regions=a,b` (atau `all`). Union OR atas `terms`, dibungkus `AND` supaya tidak bentrok dengan `search`. Kunci tak dikenal → hasil kosong (bukan semua lead). |
| `apps/web/src/app/map/MapView.tsx` | Panel "Daerah" (multi-pilih + tombol Tampilkan), pilihan diingat di `localStorage` (`map.regions`), peta refit hanya saat pilihan berubah (bukan saat refetch fokus tab). Belum ada pilihan = tidak ada fetch lead. |

**Jebakan pencocokan alamat** (dicek dari data scrape sebenarnya):
- Alamat Google campur Indonesia/Inggris: `Kabupaten Pati` / `Pati Regency`, `Kota Semarang` / `Semarang City`. Satu daerah boleh punya beberapa `terms`.
- `Pati` polos salah menangkap `Kec. Gn. Pati` (Gunungpati, Semarang), jadi daerah Pati memakai `Kabupaten Pati`, `Kab. Pati`, `Pati Regency`. Cek istilah baru dengan menghitung kecocokan di file `scrape-output/<daerah>-dokter-klinik.json` (NDJSON, field `address`) sebelum menambahkannya.
- Daerah yang berbatasan bisa tumpang tindih (mis. Blora ∩ Tuban); memilih keduanya memakai union, tidak dobel.
- Lead tanpa alamat yang cocok hanya muncul lewat opsi "Semua daerah (lambat)".

**Catatan operasional sesi ini:**
- Direktori kerja sesi bisa berpindah (mis. ke `apps/web` setelah uji lokal), sehingga `../VPS_DW/DWSSH.pem` tidak ketemu dan ssh gagal `Permission denied (publickey)` tanpa menyentuh VPS. Pakai path absolut `/d/Hilmi/Coding/Sahaibat/VPS_DW/DWSSH.pem` dan `cd` ke `Mapping` dulu untuk path sumber relatif.
- Direktori baru di VPS (`api/leads/region-counts/`) harus dibuat dulu (`mkdir -p`) sebelum `scp`.
- Satu loop `scp` lebih ringkas daripada satu `!` per file; build `docker compose build web` ±1–2 menit dan CRM mati sebentar saat recreate.
