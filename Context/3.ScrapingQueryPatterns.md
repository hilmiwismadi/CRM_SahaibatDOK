# 3. Scraping Query Patterns

Ringkasan pola query scraping per 2026-09-21 — dibaca dari riwayat nyata `scrape_jobs` di VPS (`103.93.162.31:3000/admin/scrapes`) dan isi `Mapping/scrape-queries/`. Tujuannya: referensi cepat kalau mau bikin batch scraping baru, biar polanya konsisten dengan yang sudah terbukti jalan.

## Dua pipeline berbeda — jangan tertukar

1. **Pipeline otomatis (gosom scraper)** — query berupa *frasa pencarian lokasi* ("dokter praktik mandiri Yogyakarta"), dijalankan lewat `scripts/run-scrape.ps1`/`.sh`, hasilnya di-import via `/admin/scrapes` atau `POST /api/admin/import-staging`. Ini yang tercatat di tabel `scrape_jobs` dan muncul di halaman admin.
2. **Pipeline manual batch** — nama klinik/dokter yang *sudah diketahui* (dari riset manual, bukan discovery), dientry terstruktur lewat `scripts/import-manual-batch.mjs` (`POST /api/leads` langsung, tanpa lewat `scrape_jobs`), lalu **baru** digeocode belakangan dengan menjalankan gosom pada nama-nama itu sebagai query (`manual-batch-20260906.txt`) dan menempelkan hasil lat/lng-nya lewat `scripts/merge-manual-batch-geocode.mjs` + `-pass2.mjs`. Detail lengkap sudah ada di [[2.LeadPipelineScripts]] — dokumen ini fokus ke pola *query* pipeline #1.

## Pola konstruksi query (dari isi `scrape-queries/`)

Setiap baris di file query adalah satu pencarian Google Maps penuh — lokasi harus ditulis di dalam teks query itu sendiri (lihat `docs/SCRAPER_GUIDE.md` §1). Pola yang konsisten dipakai di semua file:

### 1. Cartesian product: varian frasa × lokasi

File besar (`4kota-dokter-puskesmas-klinik.txt`, `jogja-raya-dokter-puskesmas-klinik.txt`) menyilangkan **6 varian frasa** dengan tiap kota target:

```
dokter praktik mandiri <Kota>
dokter praktek mandiri <Kota>   ← varian ejaan "praktik" vs "praktek"
praktik mandiri dokter <Kota>   ← urutan kata dibalik
dokter mandiri <Kota>           ← bentuk pendek
puskesmas <Kota>                ← kategori terpisah, tanpa kata "dokter"
klinik <Kota>                   ← kategori terpisah, tanpa kata "dokter"
```

Alasan pakai banyak varian: Google Maps mencocokkan berdasarkan bagaimana bisnis itu *mendeskripsikan diri sendiri* / dikategorikan di listing-nya, jadi ejaan/urutan kata yang beda menangkap listing yang beda pula — bukan sekadar duplikasi query yang sia-sia (dibuktikan oleh raw count 493 dari 24 baris untuk 4 kota = rata-rata ~20 hasil unik per baris, bukan hasil yang sama diulang).

### 2. ICP yang konsisten ditarget

Tiga kategori bisnis selalu sama di semua file, sesuai ICP Sahaibat DOK (lihat `Context/SahaibatExplanation/`):
- **Dokter praktik mandiri** — solo practitioner (`businessType: solo_doctor`)
- **Puskesmas** — fasilitas kesehatan masyarakat
- **Klinik** — klinik pratama/swasta (`businessType: klinik_pratama`)

### 3. Test kecil dulu, baru scale up

Riwayat file menunjukkan alur incremental:
1. `yogyakarta-dokter-praktik-mandiri.txt` — **1 baris**, satu query tunggal. Dipakai sebagai smoke test pertama (lihat "Verified real run" di `docs/SCRAPER_GUIDE.md` — 20 hasil, depth 1/concurrency 1, di bawah semenit).
2. `puskesmas-jogja-sleman.txt` — **2 baris**, masih sempit (1 kategori × 2 kota). Test kategori baru (puskesmas) sebelum digabung ke batch besar.
3. `4kota-dokter-puskesmas-klinik.txt` / `jogja-raya-dokter-puskesmas-klinik.txt` — **24–30 baris**, full Cartesian product 6 varian × 4–5 kota, dijalankan setelah pola query kecil terbukti menghasilkan lead yang relevan.

Pola ini menghindari membuang budget request (dan risiko block dari Google) untuk kombinasi query yang belum terbukti sebelum discale ke banyak kota sekaligus.

### 4. Nama file = nama job

Konvensi penamaan file di `scrape-queries/`: `<cakupan-wilayah>-<kategori-singkat>.txt`, misalnya:
- `4kota-dokter-puskesmas-klinik.txt`
- `jogja-raya-dokter-puskesmas-klinik.txt`

Nama file ini yang dipakai sebagai flag `-Name`/`-n` ke `run-scrape.ps1`/`.sh` (menentukan nama file output `scrape-output/<name>.json`), dan lazimnya juga jadi dasar `queryText` yang diisi manual di form import `/admin/scrapes` (lihat kolom `Query text` di halaman itu — bebas teks, hanya untuk catatan, tidak divalidasi terhadap isi file).

## Template untuk batch baru

Berdasarkan pola di atas, kerangka file query baru untuk kota/wilayah lain:

```text
dokter praktik mandiri <Kota1>
dokter praktik mandiri <Kota2>
dokter praktek mandiri <Kota1>
dokter praktek mandiri <Kota2>
praktik mandiri dokter <Kota1>
praktik mandiri dokter <Kota2>
dokter mandiri <Kota1>
dokter mandiri <Kota2>
puskesmas <Kota1>
puskesmas <Kota2>
klinik <Kota1>
klinik <Kota2>
```

(6 varian × N kota baris, dikelompokkan per varian seperti contoh di atas — bukan per kota — supaya konsisten dengan file yang sudah ada.)

**Contoh penerapan**: `surakarta-raya-dokter-puskesmas-klinik.txt` (dibuat 2026-09-21) — 6 varian × 6 kota (Surakarta, Sukoharjo, Karanganyar, Boyolali, Sragen, Wonogiri) = 36 baris. Catatan: Karanganyar sudah pernah ter-scrape lewat batch `jogja-raya` (job 2026-09-09) — baris untuk kota itu di batch ini kemungkinan besar akan menghasilkan `updated`, bukan `new`, saat diimpor (perilaku aman, lihat observasi re-scrape di atas), tapi tetap disertakan untuk kelengkapan cakupan "Solo Raya".

Sebelum jalan full batch untuk wilayah yang benar-benar baru: pertimbangkan smoke test 1 baris dulu (pola file #1 di atas) untuk pastikan area itu punya cukup listing relevan, baru scale ke Cartesian product penuh.
